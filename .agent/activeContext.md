## やったこと

会話本文を `gpui::list` にして**可視の発話だけ** element を作る（1 item = 1 発話 +
末尾の付随要素 = カード / 作業中 / 承認）。行テキストは**文書全体ぶん**作るので
⌘A / コピー / ヒットテストは描画状態に依存しない（#826 と同じ構え）。
器の違いは `chat_body_bounds` / `chat_scroll_to_*` / `chat_item_count` /
`chat_scroll_mark` の 1 本ずつに閉じ込め、旧経路（`TAKO_830_NO_CHAT_VIRTUAL_LIST=1`）
でも同じ意味になるようにした。

## 効果（隔離・同一バイナリ A/B・実 transcript tail 50 = 534 md ブロック）

| 1 タブのチャット枚数 | 残留 before | 残留 after | 整形した行数 |
|---|---|---|---|
| 1 枚 | 11.32 MB | **2.53 MB** | 580 → 26 |
| 4 枚 | 43.78 MB | **4.10 MB** | 2,320 → 104 |
| 8 枚 | 86.24 MB | **8.18 MB** | 4,640 → 208 |

索引の行数は 580 / 2,320 / 4,640 のまま（座標系は不変）。定常フレームは
8 枚で 0.68 → 0.41 ms。**効くのは会話の長さではなく 1 タブに何枚あるか**
（`CHAT_TAIL` = 50 で会話は頭打ちだが、表示中のペインは全部 element を作る）。

## 唯一の挙動差（意図して残した）

チャットを開いた**最初のフレームで末尾（いちばん新しい発話）**が出る。旧経路は
`ScrollHandle::scroll_to_bottom()` が前フレームの実測に依存するため初回は動かず、
tail 50 の**いちばん古い発話**から表示されていた（承認カードが出ても画面外だった）。
「既定は追従」「会話は下から読む」の設計意図どおりなので直した側を採っている。
