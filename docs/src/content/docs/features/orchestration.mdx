<div id="そもそもオーケストレーションとは" class="tako-anchor"></div>

司令塔の AI（**master**）に日本語で 1 回頼むと、master が仕事を分け、担当の AI（**worker**）を同じタブに並べて同時に進めます。見張り・確認待ちへの返事・結果の確かめ・片付けまで master が引き受けるので、あなたは最初の依頼と最後の報告を読むだけです。

<Cmd>tako master</Cmd>

スクロールすると、tako の画面が実際の流れで動きます。使い方の実例やつまずきやすい点は [tako master 実践ガイド](/features/orchestrator/) にあります。

## 長い仕事は、後任の master へ引き継ぐ

会話が長くなりすぎる前に、master は自分で後任を立てて交代します。一晩かかる仕事を任せても、途中で司令塔が息切れしません。

<OrchHandoff />

## なぜターミナルに組み込むのか

オーケストレーションは、スクリプトや tmux を組み合わせれば自作もできます。ただ、実際にやるとこんな壁に当たります。

| 自作でつまずくところ | tako では |
|---|---|
| worker がどこで動いているか見えない | 同じタブのペインに並び、画面がそのまま見える |
| 確認待ちで止まっていても気づけない | tako が形で見つけ、master が答える |
| tmux・スクリプト・MCP の設定を自分でつなぐ | `tako master` の 1 コマンド。設定ファイルは書かない |

ターミナル自身がオーケストレーションの舞台なので、外部のスクリプトは要りません。

## Windows でも使えます

Windows でも同じ流れで動きます。master と worker の操作（`tako_orchestrator_` で始まる {orchRows.length} 機能）のうち <strong>{orchSupported} 機能が、Windows の実機で確かめた「対応」</strong>です。一部だけ違うのは次の 1 つです（全体は [Windows 対応状況](/windows-support/)）。

## ほかにも

### 設定ファイルを触らなくていい

管理するプロジェクトやモデルの設定も、master に日本語で頼めば登録まで済ませます。

> 「`~/Documents/api-server` のリポジトリも管理対象に追加して」

### 再起動しても壊れない

worker は [tmux バックエンド](/features/tmux-backend/)（Windows では psmux）の上で動きます。tako を閉じても worker のプロセスは裏で動き続け、次に開いたときに画面ごと戻ります。

### プロジェクトをまたげる

worker はそれぞれ別のプロジェクトのフォルダで動けます。フロントエンド・API・ドキュメントのリポジトリを、1 つの master に任せられます。

## 1 対 1 で十分なら `tako solo`

worker に分ける必要がなく、AI と 1 対 1 で作業したいだけなら `tako solo` を使います。worker を起動せず、その AI 自身がファイルを読み、コードを書き、テストを走らせ、コミットまで進めます。

<Cmd>tako solo</Cmd>

master と同じく管理対象のプロジェクトを知っているので、`cd` しなくても「demo の README を直して」のように名前で頼めます。**まず 1 つのことを任せるなら solo、いくつも並べて進めるなら master** と覚えておけば十分です。
