Claude Code のような AI エージェントは、1 つの作業を任せている間、あなたの手が空きます。それなら「別の作業ももう 1 体に任せたい」と考えるのは自然です。このページでは、**AI エージェントを複数同時に（並列で）動かす方法**を、tako を使わないやり方も含めて 3 通り紹介し、並列にしたとたんに起きる落とし穴と避け方をまとめます。

## 先に結論

| やり方 | 向いている場面 | 手間 |
|---|---|---|
| [ターミナルのタブ + git worktree](#やり方-1-ターミナルのタブ--git-worktree) | 2〜3 体を自分の目で見ながら回す | タブの行き来と、止まった AI の見回りは自分でやる |
| [tmux で裏に回す](#やり方-2-tmux-で裏に回す) | 長時間の作業。ターミナルを閉じても止めたくない | tmux の操作を覚える。様子は自分で見に行く |
| [tako master に任せる](#やり方-3-tako-master-に任せる) | 依頼を出したら、分担・監視・報告まで任せたい | 最初に `tako setup` と `tako master` を打つだけ |

どのやり方でも、守るべきことは同じです。**同じファイルを 2 体に同時に触らせない**、**止まっている AI に気づける状態にする**、**閉じても作業が消えないようにする**。以下、順に説明します。

## 並列にすると起きること

### 同じファイルの取り合い

同じディレクトリで 2 体の AI を動かすと、片方が書き換えたファイルをもう片方が古い内容のまま上書きしたり、`git status` に 2 つの作業の変更が混ざってコミットを分けられなくなったりします。対策は 2 つです。

- **作業ツリーを分ける**: git worktree で、同じリポジトリの別ブランチを別ディレクトリに取り出し、1 体 = 1 ディレクトリにする（[やり方 1](#やり方-1-ターミナルのタブ--git-worktree)）
- **触るファイルが重なる作業は並列にしない**: 順番に 1 体ずつ進める

### 止まっている AI に気づけない

AI エージェントは、コマンドの実行許可や方針の確認を求めて**入力待ちで止まる**ことがあります。1 体なら目の前で気づけますが、3 体をタブに分けて動かしていると、裏のタブで 30 分止まっていた、ということが普通に起きます。

### どこで何が動いているか分からなくなる

エージェント本体のほかに、dev サーバー・テスト・ログの画面も増えます。タブやウィンドウが散らばり、ターミナルを閉じた拍子に作業中のエージェントまで終わらせてしまうこともあります。

### 利用枠を早く使う

同時に動かす体数が増えるほど、契約しているプランの利用枠を早く使います。上限に当たったときの動き方も決めておくと安心です（tako では、上限で止まったペインをリセット後に自動で再開させる [`tako limit-resume`](/guides/cli-reference/#tako-limit-resume) を使えます）。

## やり方 1: ターミナルのタブ + git worktree

いちばん素朴な方法です。git worktree を使うと、1 つのリポジトリから**ブランチごとに別のディレクトリ**を取り出せるので、AI 同士が同じファイルを取り合わなくなります。

```bash
cd ~/work/myapp

# 作業ごとに別のディレクトリ（と別のブランチ）を用意する
git worktree add ../myapp-login -b feature/login
git worktree add ../myapp-docs  -b fix/docs-typo

git worktree list    # 取り出したディレクトリの一覧
```

あとはターミナルのタブを作業の数だけ開き、それぞれのディレクトリで AI エージェントを起動します。

```bash
# タブ 1
cd ~/work/myapp-login && claude

# タブ 2
cd ~/work/myapp-docs && claude
```

作業が終わってブランチをマージしたら、取り出したディレクトリは片付けます。

```bash
git worktree remove ../myapp-login
```

この方法の弱点は、[止まっている AI](#止まっている-ai-に気づけない) を見つけるためにタブを見回る必要があることと、ターミナルを閉じると AI も終わることです。

## やり方 2: tmux で裏に回す

tmux のセッションの中で AI エージェントを動かすと、ターミナルを閉じても AI は動き続け、あとから同じ画面に戻れます。

```bash
tmux new -s login -c ~/work/myapp-login    # セッションを作って入る
claude                                     # セッションの中で起動する
# 作業を任せたら Ctrl-b → d で抜ける（AI は裏で動き続ける）

tmux ls                 # 動いているセッションの一覧
tmux attach -t login    # 画面に戻る
```

作業ツリーの分け方は[やり方 1](#やり方-1-ターミナルのタブ--git-worktree) と同じです。tmux で AI を動かすときのコツ（外から様子を読む・外から指示を送るときの注意）は [tmux で AI エージェントを動かす](/guides/tmux-agents/)にまとめています。

## やり方 3: tako master に任せる

tako では、**司令塔の AI（master）に日本語で頼むだけで、担当の AI（worker）が同じタブのペインに並んで立ち上がり、並列に作業します**。分担・指示・監視・報告は master がやります。

### 手順

1. [tako をインストール](/getting-started/)して、tako の中のターミナルで次の 2 つを実行します

   ```bash
   tako setup     # 初回だけ。Claude Code の導入確認や MCP の登録まで自動
   tako master    # 司令塔の AI を起動
   ```

2. 作業したいリポジトリを覚えてもらいます

   > 「`~/work/myapp` のリポジトリを管理対象に追加して」

3. 並行で進めたい作業をまとめて頼みます

   > 「myapp のログイン画面のバグ修正と、README の誤字直しを並行で進めて」

master は依頼を**成果物ごとに分け**（1 worker = 1 成果物）、誰に何を任せるかを 1 行ずつ示してから worker を立ち上げます。意図と違えば、その場で止められます。

### 同じファイルの取り合いは master が避ける

master は、別のプロジェクトの作業や、触るファイルがはっきり分かれている作業だけを並列にします。**同じファイルを触りうる作業は順番に回し**、後の worker には先の変更を壊さないよう指示に書き添えます。並列の worker 2 体が同じファイルを同時に書き換える、という状態を手順で作りません。

### 止まった AI・終わった AI は master が拾う

worker の画面は同じタブのペインとして目の前に並ぶので、何をしているかをそのまま眺められます。master は worker の**完了・入力待ち・消滅を自動で検知**し、結果を確かめてから報告します。「worker どうなってる？」と聞けば、それぞれの状況を答えます。気になる worker があれば、そのペインをクリックして直接話しかけても構いません。

```
┌─ master タブ ─────────────────────────────────┐
│ ┌─────────────┬───────────────┬──────────────┐ │
│ │  master     │  worker 1     │  worker 2    │ │
│ │  （司令塔）   │  バグ修正中…   │  誤字直し中… │ │
│ └─────────────┴───────────────┴──────────────┘ │
└────────────────────────────────────────────────┘
```

### 閉じても消えない

tmux が入っていれば、worker は [tmux バックエンド](/features/tmux-backend/)の上で動きます。tako を閉じても worker のプロセスは生き続け、次に起動したときに画面ごと戻ります。

考え方の全体像は [オーケストレーションとは](/features/orchestration/)、話しかけ方の実例やつまずきポイントは [tako master 実践ガイド](/features/orchestrator/)を参照してください。

## tako の中で手で並べる

master を使わず、自分で並べて動かすこともできます。<kbd>Cmd</kbd>+<kbd>D</kbd>（Windows は <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>D</kbd>）でペインを右に分割し、それぞれのペインで作業ディレクトリへ移って `claude` を起動するだけです。1 つのタブに並ぶのでタブを見回る必要がなく、tmux があれば tako を閉じても消えません。分割やレイアウトの操作は [タブ＆ペイン管理](/features/tabs-and-panes/)を参照してください。

## よくある質問

### 同じリポジトリで Claude Code を 2 つ動かしても大丈夫？

触るファイルがまったく重ならないなら動きますが、同じファイルを同時に書き換えると、片方の変更がもう片方に上書きされることがあります。変更がコミット前の作業ツリーに混ざるので、あとから作業ごとに分けるのも面倒です。**git worktree で 1 体 = 1 ディレクトリにする**のが安全です。tako master は、同じファイルを触りうる作業を並列にせず順番に回します。

### 何体まで同時に動かせる？

tako の側に体数の上限の設定はありません。実際の上限は、画面の広さ（ペインが小さくなりすぎると読めない）、マシンの資源、契約しているプランの利用枠で決まります。まずは 2〜3 体から始めるのがおすすめです。

### Claude Code と Codex を混ぜて動かせる？

できます。tako master の worker は、既定の系統をプロファイルで決めたうえで、1 体ずつ別の系統を指定できます。手順は [OpenAI Codex CLI](/agents/codex/) と [エージェントの選び方](/agents/)を参照してください。

### Claude Code のサブエージェントとは何が違う？

サブエージェントは、1 つの Claude Code のセッションの中で、本体が作業の一部を別の文脈に任せる仕組みです。結果は本体へ返り、あなたが途中で直接話しかける相手ではありません。このページで扱っているのは、**独立したセッションを複数立てて、別々の作業を同時に進める**方法です。両者は併用できます。

### ターミナルを閉じたら止まる？

普通のターミナルのタブで起動した AI は、タブやウィンドウを閉じると終わります。tmux のセッションの中で動かしていれば止まりません。tako は tmux があれば全ペインを tmux の上で動かすので、tako を閉じても AI は動き続けます。
